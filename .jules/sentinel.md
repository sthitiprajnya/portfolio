## 2024-06-04 - Fix Trusted Types Security Theater
**Vulnerability:** The default Trusted Types policy in `src/app/layout.tsx` was a pass-through (i.e. `s => s`), which bypassed the CSP `require-trusted-types-for` restriction and provided zero defense-in-depth against DOM XSS.
**Learning:** Next.js hydration often requires passing some HTML payloads dynamically. Strictly rejecting all scripts via Trusted Types can break chunk loading. A targeted blocking strategy (sanitizing specific known dangerous tags/patterns like `<script`, `javascript:`, `onerror=`) provides better security without breaking Webpack routing.
**Prevention:** Avoid blindly using pass-through Trusted Type policies. Implement at least basic naive sanitization or strict CSP nonces for scripts, and never return `s => s` when configuring a default policy.
